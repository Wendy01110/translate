# 实时字幕已排队结果在停止或语言切换后仍显示

> 状态：已关闭
>
> 日期：2026-10-06（Asia/Shanghai）

## 证据与影响

使用实际 `DesktopListener`、macOS / Windows 实时 presenter、Fake OCR/翻译和 UI 队列离线复现：worker 完成 `live_tick()` 并排队显示后，在 UI 线程调用停止，窗口先隐藏；随后执行旧显示回调，窗口重新显示，但 listener 已停止。相同间隙切换目标语言，也会把原语言结果显示到当前窗口。两平台、两种动作合计四个场景均复现；相关既有测试 89 项通过，尚未覆盖该队列间隙。

业务状态在 worker 提交结果时通过检查，UI 实际显示则发生在稍后的主线程回调中。macOS `callAfter` 与 Windows `call_soon` 均没有携带或重验业务状态；后台状态有效不保证排队 UI 回调仍有效。

## 范围与关闭条件

- 修复两端实际显示前的校验，覆盖结果与临时状态；停止重开后旧显示和旧隐藏不得影响新会话。
- 语言切换使已排队的旧语言结果失效，显示过程中发生停止或语言切换也不得重新前置窗口。
- 默认回归只使用 Fake 端口和 UI 队列，不读真实屏幕或剪贴板，不调用模型。
- 对应原生与公开桌面行为验证按[实施计划](../../plan/in-progress/2026-10-06-desktop-follow-through.md)执行，关闭时记录测试、结果及完成日志。

## 当前进度

已通过 `LiveResultPresenter` 将 listener 的会话/语言快照谓词延续到 UI 线程，并在实际前置前再次检查；两端显示代次同时保护旧状态、旧结果和旧隐藏请求。停止后的 `set_anchor(None)` 不使当前隐藏请求失效，正常停止仍能隐藏既有窗口。

`tests/interfaces/test_live_presentation_queue.py` 使用实际 listener / presenter 和 Fake UI 队列，对两端分别验证停止后的排队结果、语言切换、旧状态、后台停止、重开后的旧结果、旧隐藏，以及布局期间停止或切换语言，共 16 项。完整离线 606 项通过；App 组合的两项源码断言已替换为对象与回调行为验证。原生与正式 App 的不同验收层级见[本轮日志](../../logs/202610/2026-10-06-desktop-follow-through.md)。
