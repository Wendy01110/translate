# 实时 OCR 圈选会话隔离

## 当前依据

- 上一轮图像输入与截屏边界优化已完成本地实现和离线验证。本轮重新读取文档入口、当前 OCR 计划和 Git 状态，保留全部已有 WIP；当前监听器定向基线 33 项通过。
- `DesktopListener` 的圈选回调只检查 `_live_starting`，没有绑定发起圈选的会话。停止后马上重开时，旧的有效矩形回调可误启动旧区域，旧的取消回调也可清掉新一轮启动状态。
- Windows `WindowsRegionPicker._finish()` 实际通过 UI 定时回调延迟 40 ms 投递完成结果；macOS 启动圈选也可先进入主线程队列。因此回调迟到和排队启动都属于当前实现的实际路径。
- `replace_runtime()` 只在实时循环已经运行时停止，应用设置时尚未完成的圈选没有取消，之后仍可能启动循环。
- 原四层 OCR 计划仍缺 macOS 首次加载提醒的实际显示验收；本轮只处理监听器会话状态，不补做真实桌面或模型调用。

## 目标与范围

- 圈选发起时就在已有状态锁内预留会话代次；主线程排队启动、同步圈选结果和异步完成回调都携带该代次，只处理当前会话。
- 停止/取消立即使旧代次失效；旧有效矩形、旧取消结果和旧启动失败不得启动、取消或覆盖新一轮状态。
- 由圈选到运行的状态变更使用现有短临界区，复用当前循环、去重和补试逻辑；不增加新的线程种类、状态框架或依赖。
- 应用设置时一并停止正在圈选和已经运行的实时会话，用户按新设置重新圈选；目标语言栏的即时切换仍继续当前循环。
- 只修改共享监听器、直接相关离线回归和文档；不修改平台圈选 UI、翻译/OCR 配置、CLI 参数或公共结果字段。

## 执行顺序

1. 先创建本计划、保存本轮初始快照并同步文档入口。
2. 用 Fake picker、Fake 主线程队列和受控 worker 验证停止后重开、迟到回调、排队启动、启动失败和设置应用，先复现当前缺口。
3. 修改共享监听器的圈选代次与设置取消逻辑，保留同步 picker 和既有实时路径。
4. 同步用户 README、实时 OCR、桌面和架构设计；运行监听器/桌面定向与完整离线套件。
5. 回读相对快照的最终 diff、检查原有 WIP 和文档引用；验收通过后移动原计划至 `completed/` 并写完成日志。

## 验收条件

- 停止后重开时，旧有效矩形和旧取消回调均不影响新圈选；新圈选完成后只启动一次循环，重复回调不重入。
- 旧主线程队列任务不打开新的 picker；旧初始化失败不会清掉新会话的启动标志。
- 应用设置能取消未完成的圈选，使旧回调失效；按新设置可重新开始。
- 同步圈选、异步圈选、正常取消、热键停止、目标语言切换、在途任务丢弃和有限补试原行为继续通过离线验证。
- 仅使用 Fake picker、队列、截屏与模型，不触发真实 AppKit/Qt 窗口、截屏、剪贴板或外部调用；最终文档与状态一致。

## 授权与停止边界

- 不执行：真实截图/选区/剪贴板读取、真实 OCR/翻译、模型下载、依赖或环境变更、真实 `.env` 修改、App 重启、Git 提交/推送、发布或部署。
- 如需要跨项目修改、扩大到平台 UI 重写、公共契约变更或上述外部动作，停止扩展并完成已授权部分。
