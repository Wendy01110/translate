# 默认内置翻译源与输入框翻译计划

> 状态：已完成；默认 `google_web`，菜单「输入翻译…」复用现有翻译端口
>
> 创建日期：2026-08-20（Asia/Shanghai）

## 目标

把未配置时的翻译来源改成 Google 内置网页源，安装后不必先填密钥。同时提供菜单「输入翻译…」，让用户粘贴或输入文本后复用现有翻译端口。

## 当前依据

- 代码默认 `TRANSLATE_PROVIDER=openai`，无地址和模型则未就绪；`.env.example` 与设置页 fallback 已是 `google_web`。
- 用户已授权把默认源改成 `google_web`。
- [TTime 对照后的后续能力](../pending/2026-08-19-ttime-inspired-follow-on.md) 第 1 项是输入框翻译；划词/OCR 热键和菜单栏 App 已落地，真实热键验收仍待授权。
- `ai-translate text` 与 `SelectionTranslateService` 已能翻译显式文本。

## 范围与非目标

- 范围：默认 `google_web`；菜单打开输入窗口；窗口内展示原文和译文；空文本不调用上游；与划词/OCR 共用串行锁和同一翻译端口。
- 非目标：输入框热键、历史、划词工具栏、剪贴板监听、TTS、Electron。
- 非目标：为输入框再写一套翻译语义，或把结果改走划词浮窗。

## 已完成

1. 默认 `TRANSLATE_PROVIDER` 改为 `google_web`，无 `.env` 时翻译侧就绪；显式 `openai` 仍要地址和模型。
2. 菜单「输入翻译…」打开输入窗口，复用 `SelectionTranslateService`；空输入不调用上游；忙碌时返回 `busy`。
3. 产品范围、架构、配置设计、用户 README 和 TTime 后续清单已同步。

## 验收条件

- 无 `.env` 时翻译侧 `ready` 为真，`provider` 为 `google_web`；显式 `openai` 且无地址/模型时仍未就绪。
- 空输入不调用翻译端口；忙碌时输入翻译失败且不影响已有热键锁。
- 离线测试通过；默认套件不打开真实窗口、不打真实上游。
- README 写明默认内置源和「输入翻译…」。

## 授权与停止边界

- 允许：改默认来源、输入窗口、文档和离线测试。
- 需要额外授权：真实网页翻译、提交和推送。
- 出现必须引入历史、工具栏或第二套翻译链时停止。

## 剩余工作

无。输入框热键、历史和真实网页验收不在本计划。
