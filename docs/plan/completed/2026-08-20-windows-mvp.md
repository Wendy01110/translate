## 目标

在不复制翻译和 OCR 业务语义的前提下，让现有划词翻译、输入翻译、单次区域 OCR 翻译和区域实时 OCR 翻译能够从 Windows 11 x64 桌面入口运行。首版面向本地内部使用，优先保证源码安装、系统托盘、全局热键、圈选截屏、浮窗和设置可检查，并保留 macOS 现有行为。

## 当前依据

- `core`、`features`、翻译客户端、四层 OCR 适配和实时 OCR 的去重/停止语义不依赖 AppKit，可以跨平台复用。
- `app.py` 已按平台组合 macOS 与 Windows 服务；Windows 的热键、剪贴板、圈选、截屏、单实例和 PySide6/Qt Quick 桌面界面均使用独立适配，但继续复用同一 `DesktopListener` 与 feature。
- Windows 没有本地普通 Vision，自动模式从可选本地高级 PaddleOCR 开始，再进入 API 普通 OCR.space 和 API 高级模型；两套 API 不得互借配置。
- Windows 全局热键、模拟复制、屏幕坐标、DPI、系统托盘和打包只能在 Windows 交互桌面验证；macOS 离线测试不能替代。
- 当前工作区仍需保留 macOS 路径和其它计划 WIP，本计划不得覆盖、清理或混入无关改动。

## 范围与非目标

- 范围：Windows 11 x64、Python 3.12+；系统托盘；三组全局热键；选区模拟 `Ctrl+C` 与剪贴板恢复；输入窗口；设置页；单次区域圈选；固定矩形截屏；普通浮窗和实时字幕条；单实例；Windows 用户配置目录；本地源码安装入口。
- 范围：继续复用 `SelectionTranslateService`、`OcrTranslateService`、`Translator`、`OcrEngine` 和现有结果契约；Windows `auto` OCR 跳过 Vision，按本地高级、API 普通、API 高级顺序使用可用层。
- 范围：平台 I/O 可注入，默认离线测试不得读取真实剪贴板、注册真实热键、截屏或调用上游。
- 非目标：Windows 本地普通 OCR、MSIX、代码签名、自动更新、开机启动、Windows 10/ARM64 正式兼容、Electron、系统音频转写。
- 非目标：修改 macOS 已有交互、把 OCR 配置借给翻译或把翻译配置借给 OCR。

## 执行步骤

1. 为桌面组合增加平台选择，把 macOS 主线程调度、热键、权限提示和事件循环从共享监听编排中隔离。
2. 增加 Windows 剪贴板/模拟复制、全局热键、虚拟桌面区域圈选、单次与固定矩形截屏。
3. 增加 Windows 桌面主机；初版 Tk/pystray 已在后续 UI 计划中迁移到 PySide6、Qt Quick/QML 和 `QSystemTrayIcon`，所有 QML 更新回到 UI 线程。
4. 增加 Windows 用户配置路径、单实例和 PowerShell 源码安装/启动入口；依赖使用平台标记，不影响 macOS 安装。
5. 同步产品范围、架构、桌面设计、OCR 分流、配置、根 README、CLI 文案和文档索引。
6. 增加平台选择、Windows 适配和公共行为的离线测试；运行定向测试、完整离线套件和 `git diff --check`。
7. 在 Windows 11 x64 交互桌面完成热键、剪贴板、圈选、多屏/DPI、托盘、设置、实时停止和安装验收；真实模型调用仍需单独授权。

## 验收条件

- macOS 原有入口和离线测试保持通过；Windows 平台选择不导入 AppKit、Quartz 或 `fcntl`。
- Windows 能启动单实例托盘，三组热键可注册、更新和释放；注册冲突能给出可执行错误，不静默失效。
- 划词会恢复原剪贴板；无法向更高权限窗口模拟复制时，只有剪贴板来源进程与当前前台进程一致才允许手动复制降级，来源不匹配必须提示重新复制，不把旧剪贴板冒充当前选区。
- 单次圈选取消不调用 OCR；固定区域截屏有尺寸和字节上限；实时停止后不开始新的截屏、OCR 或翻译。
- 普通工作区和字幕条不在后台线程直接操作 QML；字幕条位于圈选区域外侧并避免进入下一帧。
- Windows 配置写入用户目录，密钥只显示 `set`/`unset`；Windows 设置页不提供不可用的“只本地普通 Vision”，但提供可选本地高级 PaddleOCR。
- 默认离线测试不触发真实桌面或上游；管理员目标窗口 UIPI 降级必须由真实高权限窗口、手动复制和普通权限托盘 App 联合验证，不能用同权限 Fake 替代。

## 授权与停止边界

- 允许：本地代码、测试、文档、Windows 源码安装脚本和离线验证。
- Requester 已授权项目环境、真实翻译/OCR、Windows GUI、屏幕/剪贴板、App 重启、显示缩放、Git 提交与推送；本轮不生成发布包、不签名或发布安装包。
- 出现以下情况停止：需要引入 MSIX/本机 OCR、要求管理员权限运行、默认上传剪贴板或整屏、破坏 macOS 现有路径、需要修改当前项目以外的文件。

## 当前进度

- 已完成现状核对、Windows MVP 边界和稳定设计；现有 macOS 图标/构建 WIP 未被修改或纳入。
- 已完成平台组合、Windows Unicode 文本剪贴板、`SendInput` 模拟复制、`RegisterHotKey`、虚拟桌面圈选、Pillow 截屏、PySide6/Qt Quick 工作区/设置/圈选/字幕条、`QSystemTrayIcon`、单实例和 `%APPDATA%` 配置路径；活动组合不再依赖 Tk/ttk 或 pystray。
- 普通结果浮窗已改为每次查询时来到前面、默认不持续置顶，并提供「置顶/取消置顶」按钮；实时字幕条继续保持置顶。Windows 真机已实际点击置顶/取消置顶，并用其它窗口确认普通态可被覆盖、置顶态持续在前和取消后的层级恢复。
- Windows 托盘输入、划词和单次 OCR 已改为复用同一个 Qt Quick 翻译工作区；原文可编辑、译文只读，标题行提供目标语言、翻译、置顶和复制译文，宽屏双栏、紧凑上下排列、滚动设置页、圈选尺寸反馈和明确的字幕条停止入口都已落地。真实 `Alt+E` 选区翻译、复制和 Qt 控件回归已经通过；150%/200% Qt 缩放下工作区、设置和圈选物理坐标另有本轮证据。
- 已在 Windows 11 x64 安装 Python 3.13.15 AMD64，并由 `scripts/install-windows.ps1` 创建项目 `.venv`、安装平台依赖和启动 `windows/launcher.pyw`。首次真机执行发现无 BOM UTF-8 脚本会被 Windows PowerShell 5.1 按本地代码页误读并解析失败；脚本改为带 BOM 的 UTF-8，并由安装合同测试固定。
- 已确认托盘宿主进程使用项目 `.venv\Scripts\pythonw.exe`，第二实例以退出码 1 明确拒绝；Windows 设置窗口的翻译、OCR、语言与热键三页、滚动、应用状态和保存关闭均完成真机点击，验收进程使用无写入保存回调以避免改变当前 `.env`。系统托盘图标仍不能被当前安全自动化工具识别为目标窗口，因此未用后台回调冒充托盘菜单点击。
- 已安装 PaddleOCR 3.7.0 与 PaddlePaddle 3.3.0；Windows CPU 默认 oneDNN 路径真实预测失败后，适配器仅在 Windows 传入 `enable_mkldnn=False`。PP-OCRv6 tiny 本地图片识别、真实屏幕圈选、OCR 后翻译和桌面首次加载提醒均已成功；普通与实时路径会把 Paddle 提醒路由到当前可见工作区，不再留下过期普通窗口。
- 已把当前机器的项目 `.env` 配为本机 `llm-token-router`：翻译固定到低延迟文本模型并使用 120 秒有界超时，API 高级 OCR 固定到已实证支持图片的模型；配置回读显示两侧独立就绪且密钥均为 `unset`。正式 CLI 文本翻译、强制 API 高级 OCR 和 API 高级 OCR 后翻译均已成功，托盘宿主已重启并加载当前代码/配置。
- 重启后的托盘宿主持有 `Alt+E`、`Alt+W`、`Alt+Q`：同会话重复 `RegisterHotKey` 对三组组合均返回 Windows 错误 1409，证明注册已生效。该证据不替代真实按键触发、选区复制、圈选或停止交互；应用控制在激活安全测试窗口前等待授权超时，没有发送键盘或文字。
- 当前完整离线套件 295 项通过、2 项仅因 PyObjC/macOS 专属路径跳过；`pip check` 无依赖冲突，Qt 工作区、设置、字幕条、圈选和真实 `QSystemTrayIcon` 控件回归通过。
- 已在只含固定测试文字的普通记事本页真实触发 `Alt+E`；浮窗先显示 `translating`，随后显示正确选区和 Router 中文译文。另用与选区不同的哨兵文本验证模拟 `Ctrl+C`：浮窗原文来自选区而非旧剪贴板，处理后哨兵仍在，临时守护进程再把用户原剪贴板从内存恢复，全程未输出原内容。
- 已真实触发 `Alt+W` 和 `Alt+Q`，两者均打开逐显示器半透明圈选层；圈选中的 `Alt+Q` 再次触发后立即取消并恢复原桌面。Qt 迁移后每块物理显示器各使用一个共享会话的无边框 QML 覆盖层；真实 QTest 拖动返回准确物理矩形，Esc 取消、孤立鼠标释放忽略和 200% DPI 坐标翻倍均已复核。
- 主屏固定矩形与实际拖拽的三行固定英文均经 PP-OCRv6 tiny 完整识别并由 Router 成功翻译，首次加载提醒只在真正创建 pipeline 前显示。当前机器有两块显示器，虚拟桌面为 `-1080,-258,3640,1920`；主屏覆盖层实际为 `0,0,2560×1440`，副屏覆盖层实际为 `-1080,-258,1080×1920`，负坐标客户区 OCR 也准确识别 `SECOND MONITOR OCR 2026`。
- 实时固定区域复用同一引擎的真测中，首帧、相同帧跳过、变化帧重新识别/翻译和停止核心语义均已闭合；本轮又从实际拖拽进入字幕条，观察识别中、原文、译文与本地高级脚注，点击「停止」后窗口隐藏且未重新弹出。初版在 200% 缩放下裁字，改为按内容和当前 DPI 有界增高后，在 100%、150% 与 200% 下均显示完整；系统缩放已恢复 100%。
- UIPI 手动复制降级已增加前台进程所有权门禁：Requester 明确授权并接受 UAC 后，临时管理员记事本打开固定英文，Computer Use 明确报告目标窗口完整性级别高于自动化助手。Requester 在该高权限窗口内手动 `Ctrl+A`、`Ctrl+C` 后保持前台并按 `Alt+E`，普通权限托盘 App 的工作区准确显示原文 `Elevated window selection fallback works correctly.` 与中文译文「高权限窗口选择的回退功能运行正常。」；来源不匹配的旧剪贴板仍返回 `copy_simulation_failed`。临时管理员进程和测试文件均已关闭/删除。
- 系统托盘使用真实 `QSystemTrayIcon`；本机确认系统托盘可用、图标可见，Qt 激活信号打开工作区。Computer Use 无法把任务栏通知区域识别为目标窗口，因此没有声称发送过物理托盘点击，也没有改用系统级隐蔽输入。
- UIPI 验收后发现短句翻译异常缓慢：修复前本地 Router 最新请求耗时 46.212 秒、产生 2387 completion tokens，客户端请求没有显式思考开关。新增可选 `TRANSLATE_ROUTER_THINKING`；只有明确配置时才发送 Router 私有字段，当前 `.env` 设为 `false`。修复后唯一一次短句实测的 Router 延迟为 2.695 秒、completion tokens 为 6，CLI 端到端约 4.07 秒；其它 OpenAI 兼容地址省略该配置时继续不发送 `router` 字段。
- 普通翻译工作区、设置、高 DPI、逐屏圈选、字幕条和托盘迁移已由 [Windows Qt 桌面 UI 迁移](./2026-09-01-windows-ui-optimization.md) 完成。
