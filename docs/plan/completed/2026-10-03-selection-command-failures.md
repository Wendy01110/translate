## 当前依据

- 已先读取文档入口、当前四层 OCR 计划、仓库规则、相关代码和测试；当前划词来源与监听器定向基线 49 项通过，使用项目 `.venv` 的 Python 3.13.14。
- macOS 的 `read_clipboard()`、`write_clipboard()` 和 `send_copy_key()` 仅处理子进程非零退出，没有把启动失败、超时及文本编解码失败转换为 `SelectionReadError`。共享监听器只捕获该类型，原始异常会越过结果展示路径。
- 现有界面已经定义 `clipboard_read_failed`、`clipboard_write_failed` 和 `copy_simulation_failed` 的用户提示；可以复用这些错误码及 `failure` 结果，无需增加公共字段或新的恢复框架。
- `SelectedTextSource` 已在 `finally` 中恢复原剪贴板；本轮保留该流程，并验证复制失败、读写失败和恢复失败不会调用翻译，失败后热键忙碌锁仍可释放。
- 原四层 OCR 计划仍缺 macOS 首次加载提醒的实际显示验收，本轮不扩展到真实桌面或上游调用。

## 目标与范围

- 将 macOS 剪贴板读取、写入及 `osascript` 模拟复制的 `OSError`、`TimeoutExpired` 和 `UnicodeError` 转成对应的既有稳定错误码。
- 保持命令、超时、Quartz 优先复制、辅助功能判断、剪贴板恢复及 Windows 手动复制回退规则；不新增重试，也不把保存的剪贴板作为 macOS 自动复制失败的替代文本。
- 在 infrastructure 归类系统 I/O 失败，共享 listener 继续通过现有 `SelectionReadError` 展示失败；不在 interface 中添加平台 I/O 或广泛异常兜底。
- 只修改 macOS 选区适配、对应离线回归和直接受影响的用户/设计/状态文档；配置、CLI、公共端口、结果字段及依赖不变。

## 执行顺序

1. 先保存当前 WIP 快照、创建本计划并同步文档入口。
2. 用替代子进程和合成剪贴板复现启动、超时和编解码失败，验证当前异常无法进入监听器失败结果。
3. 在三个现有命令适配函数内补齐明确的异常映射，不改动共享恢复流程。
4. 验证错误提示、失败时不调用模型、原剪贴板恢复和失败后的再次触发，运行直接相关及完整离线套件。
5. 同步用户说明、桌面热键和架构设计，回读最终 diff 与范围外 WIP；验收通过后移动原计划至 `completed/` 并记录真实验证结果。

## 验收条件

- 启动失败、超时和文本编解码失败均返回对应 `SelectionReadError`，对外只展示稳定码，不输出原始子进程结果或剪贴板内容。
- 现有成功与非零退出路径继续成立；Quartz 成功时不调用 `osascript`，三个命令沿用现有 2/2/5 秒超时。
- 读、写、复制和恢复失败进入 `JobStatus.FAILURE`，不启动翻译；复制或读取失败后可恢复时，原剪贴板仍恢复。
- 失败后再次触发可正常翻译，既有 Windows 当前前台手动复制回退、辅助功能降级和选区长度边界继续通过。
- 只运行 Fake/mock 离线验证，不操作真实剪贴板、选区、窗口或模型；最终文档、计划状态与验证一致。
