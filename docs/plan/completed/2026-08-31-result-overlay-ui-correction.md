# 普通结果浮窗 UI 纠偏计划

> 状态：已完成；macOS 菜单输入、划词与单次 OCR 已统一为同一个「翻译」工作区并通过离线与原生快照验证
>
> 创建日期：2026-08-31（Asia/Shanghai）
>
> 更新日期：2026-09-05（Asia/Shanghai）

## 目标

以用户确认的参考图为验收基准，纠正 macOS 普通划词/OCR 结果浮窗仍沿用旧系统控件和上下堆叠布局的问题；在不改变业务结果、复制、滚动和窗口层级语义的前提下使用真白、冷灰、蓝紫视觉语言，并在后续明确要求下让菜单输入、划词和单次 OCR 共用同一个「翻译」工作区。

## 实施时依据

- 当前 `interfaces/overlay.py` 仍使用 520×460 的纵向 `NSSplitView`、系统边框文本区和标题栏右上角灰色置顶按钮，只完成了层级切换，没有落实参考图的内容标题、双栏工作区、圆角编辑区和紧凑图标动作。
- 当时的 `interfaces/input_box.py` 已实现参考图对应的 720×520 默认内容区、640 宽度阈值、宽屏双栏/窄屏上下排列、真白背景、冷灰圆角文本区和蓝紫按钮，可作为同项目的视觉与几何依据；该旧实现已于 2026-09-05 移除。
- 普通浮窗现有可选中复制、未选中复制当前栏全文、各栏滚动、重复更新不重新居中、默认普通层级和进程内置顶切换必须保留。
- 用户要求普通浮窗按右侧参考图实现；此前把输入窗口视觉完成和普通浮窗置顶完成合并表述为整体视觉完成不准确，本计划单独闭合这项差距。

## 范围与非目标

- 范围：macOS 菜单输入、划词与单次 OCR 共用翻译工作区的默认/最小尺寸、标题信息层级与来源脚注、目标语言栏、原文/译文区域、宽窄响应式布局、字体、颜色、圆角、边框以及标题区翻译/图钉/复制动作。
- 范围：增加可离线验证的布局纯函数与文案合同；使用 Fake 内容生成原生 AppKit 快照，与参考图逐项复核。
- 范围：同步根 README、macOS 桌面稳定设计、文档入口、计划索引和日期化完成日志。
- 非目标：修改 Windows Tk 视觉、实时字幕条、设置页、菜单项名称、翻译/OCR 配置、结果契约或模型调用；原独立 macOS 输入窗口 WIP 保留但不再由组合入口使用。
- 非目标：新增历史、语言选择、模型选择、诊断信息、第三方 UI 依赖或图片式运行时界面。

## 设计规范

- 默认内容区 720×520，最小内容区 440×480；宽度不小于 640 时原文/译文左右等宽并排，低于阈值时上下排列。
- 窗口背景 `#FFFFFF`；文本区背景 `#F7F8FC`；主文字 `#1F2430`；次文字 `#6B7280`；普通边框 `#DDE1EA`；原文强调边框与主动作使用蓝紫色 `#4F46E5` / `#7778FF`。
- 原生窗口内部标题继续使用 `翻译` 作为窗口身份，但内容区不显示独立大标题；左上标题位直接改为目标语言选择，减少重复文案并回收纵向空间。脚注继续只展示已有翻译源或 OCR 层级，不新增诊断文案。
- 「目标语言」标签和原生下拉栏与右侧翻译/图钉/复制动作共用标题行，来源脚注使用中间剩余空间；选项复用设置页的中文、英语、日语、韩语，仅更新当前 listener，不自动翻译、不写配置。翻译请求运行期间禁用栏位，设置应用后同步持久目标；目标变化时清空实时 OCR 去重记忆。
- 菜单输入、划词与单次 OCR 原文使用可编辑、可选择、可滚动且支持撤销/粘贴的原生文本区，编辑本身不自动重新翻译；标题区提供 72×32 的「翻译」按钮和 `Command+Return`，复用现有文本翻译用例并在当前窗口更新只读译文，忙碌时禁用重复动作。临时状态原文和所有译文只读，状态页隐藏翻译按钮。标题区另使用两个 32×32 SF Symbols 小按钮，图钉切换 `pin` / `pin.fill`，复制使用 `doc.on.doc` 并只复制译文；不保留底部动作栏。
- 标准 macOS 浅色标题栏、分隔线和交通灯保留，标题文字隐藏；实时字幕条继续固定置顶且样式不变。

## 执行步骤

1. 增加普通浮窗宽/窄布局纯函数，固定目标语言、翻译与两个图标动作和正文区域的非重叠边界。
2. 按参考图重建 AppKit 内容视图，接入目标语言/脚注、两块冷灰圆角文本区以及翻译/图钉/复制译文按钮。
3. 保留复制、滚动、焦点、窗口复用、层级切换和每次新结果来到前面的原行为；补充布局与按钮状态测试。
4. 用 Fake `OverlayContent` 生成默认宽屏、窄屏和置顶状态原生快照，不读取剪贴板、选区或调用真实翻译/OCR。
5. 将参考图与最终快照在同一轮按文案、层级、结构、色彩、容器、间距和动作位置复核；迭代修正可见偏差。
6. 更新受影响文档与完成日志，运行定向测试、完整离线套件、`git diff --check` 并回读最终 diff。

## 验收条件

- 默认宽屏浮窗具备目标语言/辅助信息、左右双栏、真白/冷灰/蓝紫色彩、圆角文本区和标题区小图标，不再显示重复的内容大标题、底部大按钮或纵向系统分栏。
- 窄窗口自动改为上下排列，目标语言、脚注、图钉、复制、标签和文本区均不重叠、不裁切。
- 菜单输入、划词和单次 OCR 必须复用同一个 `OverlayPresenter` / `NSPanel`，左上直接显示目标语言选择且不显示「翻译」大标题；目标语言栏切换后不自动请求，下一次输入、划词、OCR、实时 OCR 或手动再译使用新目标，重启后的默认值仍由设置控制。翻译按钮与 `Command+Return` 使用当前已编辑原文直接再译，忙碌时阻止重复动作并把结果更新到当前译文。图钉继续准确切换普通/浮动层级并更新图标、色彩和辅助文案；复制按钮只复制译文并短暂显示成功勾号；三个按钮均保留原生按压态，实时字幕条行为不变。
- 菜单输入、划词和单次 OCR 原文保持可编辑、可选择、可复制、可滚动，临时状态原文和所有译文保持只读、可选择、可复制、可滚动；新结果更新同一窗口，空内容和长文本不破坏布局。
- 最终 AppKit 快照与参考图至少完成文案、信息层级、双栏结构、颜色/容器、间距和标题区动作六项对照；任何无法一致的原生差异写入完成日志。
- 代码、测试、稳定设计、计划状态和完成日志一致；未执行的真实调用、重启、推送和发布明确保留为未执行，Git 提交需在用户授权后单独完成。

## 完成结果

- 普通浮窗默认内容区调整为 720×520，`overlay_window_layout()` 固定 640 宽度阈值、宽屏双栏、窄屏上下排列以及目标语言/图标/正文的非重叠边界；移除底栏后正文向窗口底部扩展，移除语言专用行后正文再向上扩展。
- AppKit 内容视图已按参考图重建为左上目标语言选择、已有来源/层级脚注、原文/译文标签、真白背景、冷灰圆角文本区、蓝紫强调边框以及标题区翻译/图钉/复制按钮；重复的「翻译」大标题、旧式 `NSSplitView` 和底部大按钮均已移除。
- `app.py` 不再构造独立 `InputTranslatePresenter`，菜单「输入翻译…」改为调用现有 `OverlayPresenter.show_input()`；划词与单次 OCR 结果调用同一实例的 `show()`，原生冒烟确认三个入口的窗口对象完全相同。目标语言标签和下拉栏移到原左上标题位并与三个动作共用一行，选择后调用 `DesktopListener.set_target_lang()` 并清空实时 OCR 去重记忆；切换不自动请求、不写配置，翻译中栏位禁用，设置应用后同步选择。三种原文文本区均启用编辑、撤销、粘贴并关闭智能引号/替换；点「翻译」或按 `Command+Return` 会把当前原文交给已注入的 `DesktopListener.handle_typed_text`，后台完成后在当前工作区更新只读译文和来源脚注。临时状态保持只读且隐藏翻译按钮。图钉以浅蓝紫底 `pin` 表示下一动作，置顶后切为蓝底白色 `pin.fill`；普通态可进入鼠标所在显示器的全屏 Space 并在失焦后收起，置顶态加入所有 Space 且失焦不收起。轻灰 `doc.on.doc` 按钮只复制译文，成功后显示浅蓝紫 `checkmark` 1.2 秒再恢复；三个按钮均使用原生 momentary 按压态。
