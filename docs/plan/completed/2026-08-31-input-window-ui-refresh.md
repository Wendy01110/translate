# 输入翻译窗口 UI 更新计划

> 状态：已完成；原独立 macOS 输入窗口已按视觉稿验证，后续运行时由统一「翻译」工作区取代
>
> 创建日期：2026-08-31（Asia/Shanghai）
>
> 更新日期：2026-09-05（Asia/Shanghai）

## 目标

依据 [输入翻译窗口视觉稿](../../assets/ui/2026-08-31-input-translation-concept.png)，在不改变翻译端口、异步执行、结果契约和菜单入口的前提下，重做 macOS「输入翻译」窗口的视觉层级、空间利用和缩放行为，使原文输入、译文阅读和翻译动作在本地桌面环境中更清楚、更舒适。

## 实施时依据

- 当时的 `interfaces/input_box.py` 使用 520×480 的 AppKit 默认控件纵向堆叠，原文与译文区域均为系统边框，标题、辅助说明、空状态、焦点层级和统一视觉 token 尚未建立。
- 当前窗口已经具备可编辑原文、只读译文、`Command+Return` 翻译、后台线程执行、主线程回写、状态提示、滚动和重复打开不重新居中的行为，本轮必须保留。
- 稳定设计要求输入翻译继续复用 `SelectionTranslateService` 与同一个翻译端口；界面不得直接构造客户端、调用 HTTP 或暴露模型诊断。
- 本轮视觉稿使用真白背景、冷灰编辑区、双栏工作区、蓝紫主按钮和安静的底部状态栏；所有可交互文字仍由 AppKit 原生控件渲染，不把视觉稿当作静态界面交付。

## 范围与非目标

- 范围：macOS 输入翻译窗口的尺寸、标题与辅助说明、原文/译文编辑区、空状态、边框、圆角、字体、颜色、主按钮、焦点状态和缩放布局。
- 范围：宽窗口使用左右双栏，窄窗口恢复上下排列；两种布局均保留可滚动文本区、状态提示和翻译按钮。
- 范围：补充可离线验证的布局纯函数、文案/视觉 token 合同和输入窗口定向测试；同步桌面设计、文档入口、计划索引和完成日志。
- 非目标：修改 Windows Tk 窗口、普通划词/OCR 浮窗、实时字幕条、设置窗口、菜单栏、翻译/OCR 配置、热键、业务结果状态或模型调用。
- 非目标：新增历史、语言选择器、模型选择器、复制按钮、清空按钮、动画框架、第三方 UI 依赖或静态截图式界面。

## 设计规范

- 画布：默认内容区约 720×520，最小宽度继续覆盖窄窗口；宽布局两栏等宽，窄布局上下排列。
- 色彩：窗口背景 `#FFFFFF`，编辑区 `#F7F8FC`，主文字 `#1F2430`，次文字 `#6B7280`，边框 `#DDE1EA`，强调色 `#4F46E5`；不使用暖白底、强渐变或装饰性发光。
- 字体：系统字体；标题 22px semibold，辅助说明 13px，区块标签 13px medium，正文 15px，按钮 14px semibold，状态 12px。
- 容器：只保留两个有明确用途的编辑区，不增加外层卡片；编辑区 1px 冷灰边框与 10px 圆角，窗口自身承担主要层级。
- 允许的可见文案：`输入翻译`、`输入文字，按 ⌘↵ 翻译`、`原文`、`在这里粘贴或输入文字…`、`译文`、`译文会显示在这里`、`翻译`、`⌘ ↵` 以及现有运行时状态/错误文案；不得新增营销文案、模型状态或诊断标签。
- 图标：本轮不需要独立图标；系统标题栏交通灯由 macOS 提供，不在内容区重复绘制。

## 执行步骤

1. 把窗口几何和宽/窄布局提取为纯函数，固定默认尺寸、最小尺寸、间距和两种布局的非重叠边界。
2. 按视觉稿重建 AppKit 内容层级和统一样式，增加原文占位、译文空状态、辅助说明、底部状态/动作区和窗口缩放回调。
3. 保留翻译线程、主线程回写、`Command+Return`、滚动、忙碌门禁和重复打开位置行为，并让成功、失败、空输入和忙碌状态不破坏空状态展示。
4. 更新输入窗口定向测试、桌面热键设计、计划状态和日期化完成日志；必要时同步根 README 的使用说明，但不扩展产品范围。
5. 使用项目 `.venv` 运行输入窗口定向测试、相关界面测试、完整离线套件和 `git diff --check`。
6. 启动本地 App 的输入窗口，在不发起真实翻译/OCR 的情况下按视觉稿原生尺寸和窄尺寸截图，对照文案、布局、字体、色彩、容器、缩放和焦点完成视觉复核。

## 验收条件

- 默认窗口与视觉稿保持同一信息层级、双栏结构、真白/冷灰/蓝紫色彩、字体关系、编辑区边界和底部动作区，不出现额外可见文案或控件。
- 原文为空时显示占位，译文为空时显示空状态；开始翻译、成功、失败、空输入和忙碌状态继续使用现有结果语义，不把占位文字提交给翻译端口。
- 宽窗口两栏不重叠，窄窗口上下排列；拖动缩放时主要内容不裁切，编辑区保持可滚动，按钮和状态始终可见。
- `Command+Return`、按钮点击、后台执行、主线程回写、重复打开不重新居中和原文首焦点行为保持不变。
- 默认测试不读取剪贴板、不截屏、不注册真实热键、不调用真实翻译/OCR；本地截图只验证界面候选，不等于业务验收或部署。
- 代码、测试、稳定设计、计划索引、文档入口和完成日志一致，最终 diff 不混入范围外改动。

## 授权与停止边界

- 允许：当前项目内视觉稿、代码、测试、文档和离线验证；启动本地已有 App 只做无外部调用的界面检查。
- 需要额外授权：真实翻译/OCR、读取选区或剪贴板、真实屏幕 OCR 截取、安装或升级依赖、修改 Windows 环境、提交、推送、发布和部署。
- 出现以下情况停止：必须修改翻译/OCR 公共契约、需要新增第三方 UI 依赖、需要覆盖并行 WIP、需要把范围扩大到设置/浮窗/Windows 全套重做，或本地 `.venv` 不可用。

## 完成结果

- 高保真视觉稿已保存到 `docs/assets/ui/2026-08-31-input-translation-concept.png`；AppKit 界面按同一信息层级、色彩、字体、容器和底部动作区实现，未把图片作为运行时 UI。
- `input_window_layout()` 固定默认 720×520 内容区、640 宽度阈值、左右双栏和上下紧凑布局；窗口缩放回调统一应用纯函数结果。
- 原文/译文使用原生可滚动文本控件，增加准确占位与空状态；原文继续可编辑，译文继续只读，按钮和 `Command+Return` 仍进入原有异步翻译链。
- 输入窗口定向测试 9 项、输入入口相关测试 16 项和完整离线套件 260 项通过；`git diff --check` 通过。
- 使用内存 Fake 翻译结果完成原生 AppKit 720×520、440×520 和成功结果三种快照验证；视觉对照未发现剩余可修复偏差。桌面辅助读取因 Python 宿主 bundle 标识冲突超时，未用其替代已成功的原生内容快照。
- 稳定设计、根 README、文档入口、计划索引和 [完成日志](../../logs/202608/2026-08-31-input-window-ui-refresh.md) 已同步；未调用真实翻译/OCR。本实现、测试与文档已获用户授权纳入本次 Git 提交，未推送、发布或部署。

## 后续统一收口

- 用户后续明确要求输入翻译、划词和 OCR 统一使用当前划词样式。macOS `app.py` 因此不再构造 `InputTranslatePresenter`，菜单「输入翻译…」改为调用现有 `OverlayPresenter.show_input()`；划词与 OCR 结果继续调用同一 presenter 的 `show()`，三种入口共用同一个 `NSPanel`。统一初版曾把左上标题设为「翻译」，后续 UI 纠偏已用目标语言栏替换该可见大标题。
- 原独立输入窗口实现及其专属测试已于 2026-09-05 清理；本计划、视觉稿和测试结果继续作为历史设计与验收记录保留，不再描述当前 macOS 组合路径。清理范围与验证见 [代码与文档复核记录](../../logs/202609/2026-09-05-code-review-and-redundancy-cleanup.md)。
- 当前统一工作区的验收、测试与原生截图转由 [普通结果浮窗 UI 纠偏计划](./2026-08-31-result-overlay-ui-correction.md) 和对应完成日志记录。
