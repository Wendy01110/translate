## 目标

为 AI 翻译仓库建立可继续实施的项目框架：文档按职责和生命周期分层，代码按模块化单体放置，翻译模型与 OCR 模型用独立环境变量配置，并留下可执行的配置检查入口和离线测试。

## 完成范围

- 建立 `docs/` 默认入口、稳定设计、计划状态目录、Issue 目录、归档说明和日期化日志。
- 按使用者/Agent 分工写好根 `README.md` 与 `AGENTS.md`。
- 落地 `src/ai_translate/` 分层骨架：配置、结果契约、划词/OCR 用例、独立 HTTP 客户端、CLI `config-check`。
- 用 Fake 端口和 HTTP mock 覆盖空输入、partial 和双模型前缀隔离；文档结构测试检查标题、链接和计划索引。
- 初始化 Git 并完成本次授权范围内的首次提交。

## 验收条件

- 新成员可以从 `docs/README.md` 找到当前状态、稳定设计和下一阶段计划。
- `ai-translate config-check` 能分别回读翻译和 OCR 就绪状态，且不回显密钥。
- 翻译与 OCR 配置前缀独立；一侧缺失不得继承另一侧。
- 离线测试通过；文档相对链接存在；每个计划只出现在一个状态目录。
- 没有真实模型调用、截屏、剪贴板读取或远程推送。

## 验证

- 离线套件：`27 passed in 0.12s`。
- `config-check` 在未配置时两侧均为 `ready: false`，密钥显示 `unset`。
- 本次只证明骨架、文档和离线契约，不证明划词、OCR 或真实上游可用。详细命令见完成日志。
