## 当前情况与依据

- 当前代码已具备独立翻译/OCR 配置、两端桌面入口、四层 OCR、实时翻译去重与有限补试。使用项目 `.venv` 的 Python 3.13.14，改动前完整离线套件 357 项通过；这只证明离线契约，不能代替真实模型或桌面验收。
- 工作区已有浮窗失焦、实时翻译可靠性、设置运行时复用和 HTTP 请求边界等未提交改动，本轮保留现有实现，按任务开始时的文件快照区分本轮修改。
- `load_image_file()` 先检查文件大小再调用 `read_bytes()`：检查后文件增长时可能越过 20 MiB 边界；检查与读取之间消失、权限变化或 I/O 失败时会泄漏未归类异常。
- macOS 单次截屏在整文件读取后才检查大小；固定区域截屏没有 Windows 已有的 40,000,000 区域面积前置检查。`ScreenRect.is_usable()` 也未明确排除非有限坐标。
- 四层 OCR 原计划仍等待 macOS 桌面首次加载提醒的实际显示验收；本轮不改变该状态。开放 Issue 目录当前没有条目。

## 目标与范围

- 图片文件与 macOS 截图文件共用有界读取：已有大小检查继续提前拒绝过大文件，实际读取最多 20 MiB + 1 字节，再按读到的字节数检查超限和空图。
- 图片不存在/非普通文件、空图、类型不支持、超限和读取失败分别使用稳定错误码；不把路径、系统异常详情或图片内容写入普通输出。
- macOS 截图复用图片读取边界；系统截屏命令超时、启动或文件处理失败归为 `screenshot_failed`，正常取消仍为 `screenshot_cancelled`，临时文件继续清理。
- macOS/Windows 固定区域截屏共用 40,000,000 坐标面积上限，并在调用底层抓图前检查；Windows 按物理像素、macOS 按 AppKit 屏幕点计，不宣称限制 Retina 图像的实际像素数或原生抓图内存。矩形必须使用有限坐标，保留负坐标和反向拖拽的正常行为。
- 保持现有 OCR 分流、翻译/OCR 配置隔离、公共结果字段和 CLI 参数；不增加依赖或新配置。

## 验收条件

- 检查后增长的文件不会触发无界读取；实际内容为空或超限时明确失败。恰好 20 MiB 的合成文件仍可读取。
- 文件读取的权限/I/O 错误稳定返回 `image_read_failed`；读取期间消失返回 `image_not_found`；CLI 打印错误码并停止，不调用 OCR/翻译。
- macOS 截图文件使用相同大小边界；取消、超时和系统失败均有 Fake 验证，成功和失败后都检查临时文件清理。
- 两端的过大区域在调用 grabber 前失败；恰好坐标面积上限的区域、负坐标和反向拖拽仍可工作；非有限坐标不会进入抓图。
- 定向与完整离线测试通过，文档链接与计划状态一致，最终 diff 不覆盖已有 WIP。
