## 目标与范围

减少设置应用造成的无效客户端构造和 Paddle 重复初始化；补齐桌面输入、CLI、OCR 后翻译及 OpenAI 兼容源的翻译输入长度检查，并让现有 HTTP 客户端有界读取响应。

实现位于 bootstrap/app 的组合与设置保存路径、core 共享长度常量、既有翻译用例和 infrastructure HTTP 适配，不新增依赖、配置项或后台服务。保留已有浮窗失焦修改及上一轮实时翻译可靠性改动。

## 实施与验收

1. 桌面运行时保存翻译、OCR 实例；设置未变，或仅修改语言、热键、模型列表时复用现有实例。翻译请求配置变化只替换翻译侧；OCR 配置变化才替换 OCR 侧。两类 feature 复用同一个翻译客户端，翻译/OCR 配置继续独立。
2. 统一翻译输入上限为现有内置/官方源使用的 8000 字符，超限不调用翻译端口或 HTTP；OCR 后翻译超限保留识别原文并返回 partial，不自动拆分、截断翻译或补试。
3. HTTP 最终响应按解码后字节检查，最多允许 2,000,000 字节进入解析，超限关闭流并返回稳定错误；翻译、网页会话页、两层 API OCR 均覆盖，不再先完整下载再检查。HTTP 错误不需要解析或保留上游正文。
4. Fake pipeline 验证连续识别在无关设置变化后只初始化一次，相关 OCR 配置变化后重建；MockTransport 验证长度边界、读取中止/关闭、压缩响应边界及原有正常协议。执行定向与完整离线测试、文档检查和 git diff --check。
5. 同步用户说明、配置/架构设计、状态入口与完成日志，完成后移动本计划原文件。

## 授权与停止边界

本轮仅做本项目本地实现与离线验证，不读取或修改真实 .env，不初始化真实 OCR 模型，不调用上游、不截屏或读取剪贴板，不重启 App、不安装依赖、不提交或发布。真实时延与桌面体验不属于本轮验收；若需要上述动作则停止该扩展并说明。原四层 OCR 计划的 macOS 首次提醒验收继续保留。
