- 本地文件和截屏已有单张 20 MiB 上限，但 CLI 的 `--pages` 会一次读入全部文件，没有页数或累计字节预算；高级 OCR 随后为全部图片构造 base64 请求。
- OCR 端口支持直接传入图片字节。Vision、Paddle、高级 HTTP 以及路由入口没有共同的单张/整批边界，用例的空图检查也不能拒绝超限输入；只约束文件来源不足以保护这些入口。
- API 普通 OCR.space 已有单张 1,000,000 字节限制与多页拒绝；这些提供方限制应在项目的整批输入预算内继续生效。配置就绪判定、四层次序和有效输入的 fallback 不需要改变。
- 当前四层 OCR 计划仍只缺 macOS 首次 Paddle 加载提醒桌面复验，本轮不以离线测试替代该验收。

## 目标与范围

- 本项目单次 OCR 最多接受 10 页，每张继续最多 20 MiB，全部原始图片字节合计最多 20 MiB；阈值允许等号。这是本地工具的固定输入预算，不声明为提供方限制或进程内存上限。
- 在 `core/limits.py` 定义预算，并用一个纯 core 校验函数复用空图、单张、页数和累计字节检查，减少 OCR 适配与用例重复判断。
- CLI 在读取文件前拒绝页数超限，逐张读取后检查累计预算，首次超限即停止继续读文件；来源失败退出码为 2，不调用 OCR/翻译。
- 路由、各 OCR 适配与 OCR 翻译用例在识别、Paddle 初始化、base64 编码或发送请求前拒绝超限，不把全局超限作为尝试其它层的理由。直接端口/用例返回 `failure`，保留原就绪错误优先级与 OCR.space 更严格的有效输入限制。
- 新增稳定错误码 `ocr_too_many_pages` 与 `ocr_batch_too_large`，单张超限沿用 `image_too_large`，空图沿用 `empty_image`；同步 CLI 帮助、用户提示、端口文档和配置示例说明，不增加参数、环境变量、结果字段或状态。
- 不自动分批、截断、裁图、扩展重试或并行；不修改平台截屏实现、本地解码像素限制、翻译语义或客户配置。

## 验收条件

- 11 页在文件读取前失败，10 页合法小图继续按原顺序识别；超限输入不会进入任一 OCR 层或翻译。
- 累计 20 MiB 与单张 20 MiB 可接受，任一超过时返回明确错误；累计检查不会把两张各自合法的大图当作合法整批输入。
- CLI 超限后不再读取后续路径，不输出文件路径或图像内容；截图和单图入口也遵守相同字节预算。
- 路由所有模式、两个 tier 组合和四层直接适配共同拒绝非法输入；拒绝发生在 Vision 回调、Paddle 提醒/初始化/解码、base64 编码与 HTTP 之前。
- OCR 翻译与实时 OCR 的实际处理路径拒绝超大图，不调用 OCR/翻译、不保留上一句成功译文；已有去重和有限补试行为保持。
- 合法输入继续保持四层 fallback、强制模式、OCR.space 1 MB、Unlimited-OCR/通用视觉合同和 `partial` 原文保留；不新增 `config-check` 字段。
- 文档、固定常量、CLI 帮助与用户错误提示一致，全部验证为离线 Fake/mock。
