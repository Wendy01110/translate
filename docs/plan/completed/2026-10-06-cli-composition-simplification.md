# CLI 服务构造精简与后续优化取舍

> 状态：已完成
>
> 创建日期：2026-10-06（Asia/Shanghai）

## 目标与依据

在四层 OCR 最后一项原生提醒验收与文档收尾后，按 Requester 要求复查项目可继续优化和精简的地方。精简前普通 CLI、macOS CLI 和 Windows 截图 CLI 都构造三类服务；每条命令实际只消费其中一类，却创建两套 OCR 组合和两个翻译客户端。

## 范围与验收

- 在现有 App 组合入口按首个子命令只创建 `text`、`ocr` 或 `ocr-translate` 所需的用例，三个平台复用同一处公共构造。
- 保留平台截图/选区回调、图片读取、语言、CLI 参数/输出/退出码与桌面共享运行时；不增加依赖、接口、框架、缓存或新的产品能力。
- 用 Fake 工厂统计 OCR/翻译构造次数，并通过 CLI 执行验证文本、OCR 和 OCR 后翻译输出；运行受影响 App/CLI/composition/架构测试、完整离线套件、文档与 diff 检查。
- 把已落实的精简与仍待实施的优化明确区分，记录下一步优先级和证据，不提前实施历史、工具栏、剪贴板监听或系统音频转写。

## 副作用与停止边界

本轮仅本项目代码、测试和文档，不调用上游、不读取屏幕/剪贴板、不修改真实配置、不下载模型、不安装依赖、不重启 App。Git 提交与推送沿用当前任务 Requester 的明确授权，实际执行后才记为完成。需要修改公共契约、扩大产品范围或改变独立项目时停止扩展。
