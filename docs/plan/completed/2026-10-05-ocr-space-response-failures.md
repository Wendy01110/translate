## 当前依据

- 已按文档入口读取当前四层 OCR 计划，核对工作区、现有 diff、配置加载、客户端、路由、OCR 翻译用例和相关测试；项目 `.venv` 为 Python 3.13.14，定向基线 47 项通过。
- `OcrSpaceEngine` 在 JSON 解码后用集合判断 `OCRExitCode` 和 `FileParseExitCode`。上游若把任一字段返回为列表或对象，集合查找会抛出 `TypeError`，无法转换为现有失败结果，自动模式也无法继续 API 高级层。
- 最终响应已有 2,000,000 字节解析上限，但字节上限不能排除过深 JSON 嵌套；当前 JSON 解码只捕获 `ValueError`，解码递归失败仍可能逃出 OCR.space 适配。
- 现有约定已把无法提取有效文字的普通 API 响应归为 `empty_ocr_text`，无法解码的 JSON 归为 `invalid_json`；可以复用这些错误，不增加公共结果字段、配置或路由机制。
- 已保存 63 个初始 WIP 文件哈希和 7 个相关文件副本。本轮只处理 OCR.space 的响应失败边界，原四层计划缺少的 macOS 首次加载提醒真机证据继续保留。

## 目标与范围

- OCR.space 的列表/对象状态码不再抛出异常；整次状态异常时返回 `empty_ocr_text`，单条结果状态异常时跳过该条，保留其它合法结果的原有顺序与清理行为。
- JSON 解码因嵌套过深失败时返回现有 `invalid_json`；不扩大响应字节上限、不记录原始响应或异常详情。
- 有效整数/字符串状态码、缺省单条状态码、HTTP/超时/响应大小错误和请求合同保持原有语义，不引入新的状态码转换或提供方假设。
- 用具体 OCR.space HTTP mock 与既有路由/翻译 Fake 验证：`auto` 继续 API 高级后只翻译其成功文字；强制 `standard` 保留普通层失败且不调用高级或翻译。
- 同步用户 README、OCR 分流设计、当前文档入口和计划状态；不修改配置、核心契约、桌面实现、其它 OCR/翻译提供方或依赖。

## 验收条件

- 两级状态码为列表或对象时返回结果，不抛 `TypeError`；失败结果不携带合成上游文字、错误详情或原始响应。
- 合法整数/字符串状态码和省略单条状态码继续识别；跳过异常结果后仍按顺序保留其它合法文字。
- 响应字节预算内的过深 JSON 不抛递归异常，稳定返回 `invalid_json`。
- `auto` 经实际普通客户端失败后调用高级 Fake 一次，并只把高级成功原文交给翻译；强制 `standard` 返回失败，不调用高级或翻译。
- 所有验证为本项目 `.venv` 内的 Fake/HTTP mock；范围外已有 WIP 保持原样。
