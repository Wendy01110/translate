# 划词翻译与 OCR 翻译首期实现计划

> 状态：待进行
>
> 创建日期：2026-08-19（Asia/Shanghai）

## 目标

把当前仓库从“可安装、可检查配置、用例可离线验证”推进到本机可用的两条用户路径：划词翻译和 OCR 翻译。翻译模型与 OCR 模型继续使用独立环境变量，互不顶替。

## 当前依据

- 当前代码已提供 `SelectionTranslateService`、`OcrTranslateService`、独立的 `TRANSLATE_*` / `OCR_*` 配置，以及 HTTP 客户端骨架；证据见 `src/ai_translate/` 与 `tests/`。
- `ai-translate config-check` 只回读配置，不调用上游。
- 仓库尚无全局热键、选区读取、截屏圈选或结果浮窗。
- 已知未知项：使用者最终选择的翻译模型、OCR 模型、桌面展示方式和触发热键尚未指定；本计划不得把示例地址或某个本地 router 写成既定上游。

## 范围与非目标

- 范围：为翻译和 OCR 客户端补齐可授权的真实调用；为划词提供文本来源和最小结果展示；为 OCR 翻译提供图像来源、识别后再翻译；同步 README、配置说明和测试。
- 范围：空文本、空识别、未配置、超时和上游失败继续按 `success` / `partial` / `failure` 返回。
- 非目标：文档级翻译、浏览器扩展、翻译记忆、多用户服务、默认自动上传剪贴板或屏幕内容。
- 非目标：把 OCR 图像直接交给翻译模型，或在一侧未配置时回退到另一侧。

## 执行步骤

1. 在获得真实调用授权后，用当前配置打通文本翻译 CLI，并保留脱敏日志与超时边界。
2. 实现划词文本来源：至少支持显式文本参数，再按本机能力增加选区或剪贴板读取；读取用户内容前必须有当次授权。
3. 实现 OCR 图像来源：至少支持本地图片文件，再增加屏幕圈选；图像只发给 OCR 客户端。
4. 把 OCR 文本送入既有翻译端口，识别成功但翻译失败时返回 `partial` 并保留原文。
5. 选择最小本机展示方式（先 CLI，再评估轻量浮窗），不提前引入未验证的桌面框架。
6. 同步用户文档、配置说明、计划状态和定向测试；未授权的热键常驻、截屏或付费调用保持未实现。

## 验收条件

- 配置了 `TRANSLATE_*` 后，显式文本可以走翻译端口并得到可分类结果；未配置时不发起请求。
- 配置了 `OCR_*` 后，显式图片可以抽出文本；再配置翻译后可以把识别文本译出。OCR 成功、翻译失败时结果为 `partial`。
- 两侧环境变量仍然独立；针对一侧的测试不得读取另一侧密钥或地址。
- 根 README 的快速开始仍然可执行；新增命令的成功标准和失败边界写清楚。
- 定向测试和文档结构测试通过；`git diff --check` 无新增格式错误。

## 授权与停止边界

- 允许：继续扩展离线 Fake/mock 测试、CLI 参数、文档和本机文件读取的接口设计。
- 需要额外授权：真实翻译调用、真实 OCR 调用、读取剪贴板/当前选区、屏幕截取、安装新的桌面依赖、提交之外的推送。
- 出现以下情况时停止：需要把两套模型合成一套配置、需要上传用户内容到未配置上游、或桌面方案会显著扩大依赖且没有明确选型。
