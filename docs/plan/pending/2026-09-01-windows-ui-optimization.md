# Windows 桌面 UI 优化计划

> 状态：待进行
>
> 创建日期：2026-09-01（Asia/Shanghai）

## 目标

在不改变翻译、OCR、配置和热键业务语义的前提下，统一 Windows 11 x64 的普通翻译工作区、设置、圈选、实时字幕条和托盘体验。优先使用现有 Tk/ttk、Segoe UI 与系统窗口行为，先解决信息层级、窗口重复、DPI 裁切和状态反馈，再考虑装饰性细节。

本计划只确定后续实施顺序、影响面和验收边界，本轮不修改 Windows UI 代码、不启动 Windows App、不读取剪贴板或屏幕，也不调用真实翻译/OCR。

## 当前依据

- `WindowsOverlayPresenter` 当前是 560×430 的普通结果窗，纵向展示标题、原文、译文、来源和「置顶/取消置顶」；新结果显示时前置，只有用户置顶后才持续保持最前。该层级序列已有离线合同测试，Windows 真机按钮与任务栏前后层级仍未验收。
- `WindowsInputTranslatePresenter` 当前是独立的 600×520 输入窗，具有可编辑原文、只读译文、「翻译」按钮和 `Ctrl+Enter`；它与划词/OCR 结果窗重复维护文本区和窗口状态，也不能直接复用结果窗的置顶、复制和来源展示。
- `WindowsSettingsPresenter` 当前是 640×610 的三页签窗口，配置语义已经闭合，但在高 DPI、小屏和字段较多的 OCR 页缺少滚动与视觉密度验收。
- `WindowsRegionPicker`、`WindowsLiveOverlayPresenter` 和 `WindowsTray` 已分别提供圈选提示、固定置顶字幕条和热键菜单；真实热键、固定区域截屏、多屏负坐标与实时核心循环已有证据，实际鼠标拖拽、完整字幕条关闭、托盘菜单和输入窗口仍待人工交互验收。
- macOS 统一翻译工作区可作为信息层级和状态语义参考，但 Windows 应保留系统字体、ttk 控件、`Ctrl` 快捷键、任务栏和 Per-Monitor DPI 行为，不逐像素复制 AppKit 界面。

## 前置门禁

1. 先用当前未优化版本完成 Windows MVP 中尚未闭合的实际鼠标圈选、托盘菜单、输入窗口、普通浮窗置顶/取消置顶和字幕条关闭基线，记录哪些问题是现有交互缺陷、哪些只是视觉问题。
2. 在 Windows 100%、150% 和 200% 缩放下分别保存设置、输入、普通结果、圈选和字幕条的无敏感内容截图；至少覆盖主屏和一块副屏，不用 macOS 截图代替。
3. Requester 确认统一工作区的结构候选后，才把本计划从 `pending/` 移到 `in-progress/` 并开始代码实施；未确认时不先做大范围 Tk 控件重排。

## 分阶段实施

### 阶段 1：Windows 视觉基线与轻量样式

- 在现有 `interfaces` 层集中定义 Windows 专用字体、颜色、间距、圆角不可用时的替代边界和 ttk 状态样式；只有多个窗口真实复用时才提取 helper，不为缩短文件增加空抽象。
- 保持 Tk/ttk 和现有依赖，不引入 Electron、Qt、WinUI、主题框架或新的图标包。优先使用系统控件的 hover、focus、disabled 和键盘导航状态。
- 为宽屏/紧凑布局、窗口最小尺寸和 DPI 换算提取可离线测试的纯函数；布局不得依赖固定像素假设后再在 Windows 上补丁式修正。

### 阶段 2：统一普通翻译工作区

- 让托盘「输入翻译…」、划词结果和单次 OCR 结果复用同一个 Windows 工作区与同一个窗口对象；托盘输入首次打开时清空两栏并聚焦原文，后续结果更新同一窗口。
- 原文可编辑，译文只读；修正划词/OCR 原文后只调用已注入的 `DesktopListener.handle_typed_text`，不得再次读取选区、截屏或调用 OCR。
- 标题区提供目标语言、翻译、置顶/取消置顶和复制译文；目标语言切换只更新当前运行时，不自动请求、不直接写配置，持久默认仍由设置页保存。
- 翻译按钮与 `Ctrl+Enter` 使用同一忙碌门禁；请求期间禁用翻译和目标语言，临时状态保持只读，成功、`partial`、`failure` 和空输入继续使用现有结果语义。
- 宽度充足时采用原文/译文双栏，紧凑宽度改为上下排列；两栏独立滚动，不因来源脚注、长错误或 200% DPI 裁掉正文和动作。
- 普通结果继续“显示时前置、用户置顶后才持续最前”，置顶状态只保留到当前进程退出；实时字幕条不复用这个可取消状态。
- 在统一工作区完成离线合同和 Windows 真机验收前保留旧输入 presenter 的可回退路径，不提前删除可运行实现。

### 阶段 3：设置窗口可读性与高 DPI

- 保持翻译、OCR、语言与热键三组语义和现有配置字段，重新整理标签、说明、错误与保存状态；不新增配置名，也不让翻译与 OCR 互借地址、密钥、模型或超时。
- OCR 字段较多的页面增加有界滚动或等价紧凑布局，确保 100%～200% 缩放和最小窗口下仍能访问所有字段与底部按钮。
- 对当前来源无关的字段只做明确提示或禁用，不静默删除已保存值；API key 继续遮挡，普通状态与错误信息不得回显密钥、原始图片或未脱敏上游响应。
- 「应用」继续写入并重建运行时但保持窗口打开，「保存」成功后关闭；忙碌、成功、校验失败和写入失败必须有稳定且不跳动的反馈。

### 阶段 4：圈选、实时字幕条与托盘

- 圈选层保留跨虚拟桌面和负坐标合同，优化说明、选区边框、拖拽尺寸反馈与 Esc 取消可见性；取消、过小区域和重复触发仍不得截屏或调用上游。
- 实时字幕条继续固定置顶且不抢焦点，明确原文、译文、识别中/失败状态和停止入口；窗口仍放在圈选区域外侧，不进入下一帧截图。
- 托盘菜单保留划词、截图、实时开停、输入、设置和退出；统一动词、热键提示与运行中状态，不加入模型诊断、密钥或原始内容。
- 先使用 Fake 端口和固定测试文本验证全部界面状态；真实桌面截屏、选区、剪贴板和 Provider 调用仍按各自授权边界执行。

## 候选影响面

- 组合：`src/ai_translate/app.py`，负责让 Windows 菜单输入和普通结果复用同一 presenter，并同步设置后的运行时语言。
- 普通结果、圈选、字幕条和托盘：`src/ai_translate/interfaces/windows_desktop.py`。
- 设置与旧输入窗口：`src/ai_translate/interfaces/windows_views.py`；旧输入实现只在统一工作区验收后停止组合，是否删除另行核对引用与回退需要。
- 公共状态与文案应继续复用 `interfaces/overlay.py`、`interfaces/input_box.py` 和 `interfaces/settings.py` 中的稳定格式化与选项，不复制业务判断。
- 测试重点放在 `tests/interfaces/test_windows_ui.py`、`tests/test_app.py`、架构测试和文档结构测试；如果拆出新的纯布局模块，再增加同层定向测试。

## 验收条件

- 托盘输入、划词和单次 OCR 在 Windows 复用同一个普通工作区；原文可编辑、译文只读，OCR 修正后再译不触发 OCR。
- 目标语言、翻译、复制、置顶和键盘操作在普通、忙碌、成功、`partial`、`failure` 与空输入状态下都有明确且可测试的行为，不产生重复请求。
- 100%、150% 和 200% 缩放下，普通工作区、三页设置、圈选提示和字幕条没有控件重叠、不可达按钮、正文裁切或跨屏坐标漂移；主屏与副屏至少各验收一次。
- 未置顶普通窗口可以被其它窗口覆盖，置顶后持续保持最前，取消置顶恢复；实时字幕条始终置顶但不抢焦点。Windows 真机证据与离线 Fake 证据分别记录。
- 设置页仍只写当前解析到的一份配置文件，密钥只以遮挡形式编辑；所有现有配置合同、四层 OCR 顺序和三组热键语义保持不变。
- 默认测试不打开真实窗口、不读取剪贴板、不截屏、不注册热键、不调用真实上游；定向测试、完整离线套件、文档结构测试和 `git diff --check` 全部通过。
- Windows 真机最终至少走通托盘输入、划词、单次圈选 OCR、目标语言切换、手动再译、复制、置顶/取消置顶、设置应用/保存、实时开始/停止和 App 重启；其中 Fake 结果只证明 UI，不能替代 Provider 或业务正确性。

## 非目标

- 不在本计划实现历史记录、划词工具栏、剪贴板监听、TTS、深色主题/主题商店或 macOS 界面改版。
- 不引入 Electron、Qt、WinUI、WebView、多进程前端或新的服务端；不顺带制作 MSIX、签名、自动更新和正式发布包。
- 不借 UI 优化改变公共结果状态、配置名、Provider 合同、OCR 分流、热键默认值或剪贴板安全边界。
- 不把本地截图或离线测试写成 Windows 整体可用、部署完成或业务验收通过。

## 授权与停止边界

- 本轮允许：创建并索引本计划、同步相关状态文档、运行本地离线文档/代码测试、提交并推送本次文档。
- 后续实施需要重新授权：移动计划到 `in-progress/`、修改 Windows UI 代码、打开或重启 Windows App、读取选区/剪贴板、真实圈选截屏、真实翻译/OCR、提交、推送、打包、签名或发布。
- 出现以下情况停止：需要新增桌面框架或付费依赖、必须改变翻译/OCR 业务语义、需要管理员权限、无法保留 DPI/多屏合同、会覆盖 macOS 或其它并行 WIP，或视觉改动范围扩大到本计划外功能。
