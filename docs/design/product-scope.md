# 产品范围

本文适用于本仓库的首期产品边界，面向维护者和后续实现 Agent。它回答“这个软件长期要解决什么问题”，不记录某次实现进度。

## 目标与非目标

- 目标：在本机把用户指出的一小段外文变成可读译文。指出方式只有两种：划词得到的文本，以及对屏幕或图片做 OCR 后再翻译。
- 目标：翻译和 OCR 使用两个独立模型，分别用环境变量配置地址、密钥、模型名和超时。
- 目标：空选区、空识别结果、未配置模型、超时和上游失败都按原边界返回，不把控制面成功写成译文成功。
- 非目标：文档级对照翻译、字幕同传、PDF 全书翻译、术语库/翻译记忆、浏览器扩展和多人在线服务。
- 非目标：用同一个模型同时承担 OCR 和翻译，或在一侧未配置时自动改走另一侧。
- 非目标：默认自动上传剪贴板、截屏或选区内容。

## 关键术语

| 术语 | 含义 |
| --- | --- |
| 划词翻译 | 用户选中或复制的文本进入翻译端口，得到译文 |
| OCR 翻译 | 图像先进入 OCR 端口得到文本，再把该文本交给翻译端口 |
| 翻译模型 | 只负责文本翻译的上游，由 `TRANSLATE_*` 配置 |
| OCR 模型 | 只负责从图像提取文本的上游，由 `OCR_*` 配置 |
| 就绪 | 对应模型的 `BASE_URL` 与 `MODEL` 均非空；不表示上游可调用或结果正确 |

## 主流程

划词翻译：

```text
文本来源（选区或显式输入）
  -> 规范化与空文本门禁
  -> 翻译端口
  -> 划词结果
```

OCR 翻译：

```text
图像来源（截屏、圈选或显式图片）
  -> OCR 端口
  -> 空识别门禁
  -> 翻译端口
  -> OCR 翻译结果
```

OCR 成功而翻译失败时，结果状态为 `partial`，必须保留已识别文本。任一步在调用前发现对应模型未配置，结果状态为 `failure`，不得改走另一模型。

## 失败与边界

- 空文本、纯空白、空图像或 OCR 未抽出文本：`failure`，不调用或不再继续调用翻译模型。
- 翻译上游失败：划词路径为 `failure`；OCR 路径在已有识别文本时为 `partial`。
- 超时、HTTP 错误和无法解析的上游响应都视为当次失败，不重试成另一模型。
- 用户没有明确授权时，不得读取剪贴板、捕获屏幕或发送真实上游请求。

## 变更与验证要求

- 修改产品范围时，同步 [架构设计](./architecture.md)、根 `README.md` 和当前实现计划。
- 新增第三种输入方式前，必须先更新本文的目标/非目标，再改代码。
- 范围变化后运行文档结构测试，并回读 README 的“尚未实现”表述是否仍与代码一致。
