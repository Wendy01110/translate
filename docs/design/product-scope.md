# 产品范围

本文适用于本仓库的首期产品边界，面向维护者和后续实现 Agent。它回答“这个软件长期要解决什么问题”，不记录某次实现进度。

## 目标与非目标

- 目标：在本机把用户指出的一小段外文变成可读译文。指出方式有四种：划词得到的文本、对屏幕或图片做一次 OCR 后再翻译、锁定屏幕区域后定时 OCR 再翻译、以及在输入窗口粘贴或键入的文本。
- 目标：翻译和 OCR 使用两套独立配置。翻译可在免密钥网页源（Google / Bing / DeepL 内置）与官方或 OpenAI 兼容源之间切换，仍只读 `TRANSLATE_*`。
- 目标：空选区、空识别结果、未配置模型、超时和上游失败都按原边界返回，不把控制面成功写成译文成功。
- 非目标：文档级对照翻译、系统音频同传、PDF 全书翻译、术语库/翻译记忆、浏览器扩展和多人在线服务。
- 非目标：整屏逐帧 OCR、下载或破解视频平台字幕接口。
- 非目标：用同一个模型同时承担 OCR 和翻译，或在一侧未配置时自动改走另一侧。
- 非目标：默认自动上传剪贴板、截屏或选区内容。

## 关键术语

| 术语 | 含义 |
| --- | --- |
| 划词翻译 | 用户选中或复制的文本进入翻译端口，得到译文 |
| 输入翻译 | 用户在输入窗口粘贴或键入的文本进入同一翻译端口，得到译文 |
| OCR 翻译 | 图像先进入 OCR 端口得到文本，再把该文本交给翻译端口 |
| 实时 OCR 翻译 | 用户锁定一块屏幕区域后，按有界间隔截取该区域，画面或文字未变则跳过，再走同一条 OCR 翻译路径 |
| 翻译上游 | 只负责文本翻译，由 `TRANSLATE_*` 配置；来源为网页内置或官方/兼容接口 |
| OCR 模型 | 只负责从图像提取文本的上游，由 `OCR_*` 配置 |
| 就绪 | 网页内置源无需密钥即可就绪。OpenAI 兼容源需要 `BASE_URL` 与 `MODEL`；官方 DeepL/Google 需要密钥；Microsoft 需要密钥和区域。就绪不表示上游可调用或结果正确 |

## 主流程

划词翻译：

```text
文本来源（热键模拟复制的选区）
  -> 规范化与空文本门禁
  -> 翻译端口
  -> 划词结果 / 浮窗
```

输入翻译：

```text
文本来源（输入窗口中粘贴或键入）
  -> 规范化与空文本门禁
  -> 翻译端口
  -> 输入窗口译文栏
```

OCR 翻译：

```text
图像来源（本地图片或 macOS 圈选截屏）
  -> OCR 端口（Unlimited-OCR 网关合同）
  -> 去掉版面标记
  -> 空识别门禁
  -> 翻译端口
  -> OCR 翻译结果
```

实时 OCR 翻译：

```text
锁定屏幕矩形
  -> 按间隔截取该矩形
  -> 画面指纹未变则跳过
  -> 同一 OCR 端口
  -> 识别文本未变则跳过翻译
  -> 同一翻译端口
  -> 字幕条浮层（放在矩形外侧）
```

OCR 成功而翻译失败时，结果状态为 `partial`，必须保留已识别文本。任一步在调用前发现对应上游未配置，结果状态为 `failure`，不得改走另一翻译源或 OCR 配置。

## 失败与边界

- 空文本、纯空白、空图像或 OCR 未抽出文本：`failure`，不调用或不再继续调用翻译模型。
- 翻译上游失败：划词路径为 `failure`；OCR 路径在已有识别文本时为 `partial`。
- 超时、HTTP 错误和无法解析的上游响应都视为当次失败，不重试成另一翻译源。
- 用户没有明确授权时，不得读取剪贴板、捕获屏幕或发送真实上游请求。

## 变更与验证要求

- 修改产品范围时，同步 [架构设计](./architecture.md)、根 `README.md` 和当前实现计划。
- 新增第三种输入方式前，必须先更新本文的目标/非目标，再改代码。
- 范围变化后运行文档结构测试，并回读 README 的“尚未实现”表述是否仍与代码一致。
