## 任务边界

按用户确认的右侧参考图重做 macOS 普通结果浮窗，并在后续要求下把菜单输入、划词与单次 OCR 统一为同一个「翻译」工作区；保留业务结果、复制、滚动、窗口复用和置顶层级语义，不修改 Windows 视觉、实时字幕条、设置、翻译/OCR 配置或真实 Provider 行为。

## 完成内容

- 默认内容区从 520×460 调整为 720×520；`overlay_window_layout()` 以 640 为宽度阈值，宽屏使用原文/译文左右等宽双栏，窄屏恢复上下排列，标题区动作在两种布局下均不与目标语言选择重叠。
- AppKit 视图使用左上目标语言选择、已有翻译源/OCR 层级脚注、13px 区块标签、15px 正文、真白背景、冷灰圆角文本区和蓝紫强调；重复的「翻译」大标题、旧式 `NSSplitView`、系统方框边框和标题栏右上角灰色按钮已移除。目标语言和三个动作合并到同一行后，720 宽屏文本区增高 32px，440 紧凑布局的上下文本区各增高 16px。菜单输入、划词和单次 OCR 原文文本视图可编辑、撤销和粘贴；编辑本身不自动请求，点右上「翻译」或按 `Command+Return` 后才用当前文本直接再译。译文和临时状态原文只读。
- 底部大置顶按钮和分隔线已按用户追加参考删除；标题区右侧增加 72×32 翻译按钮、32×32 图钉和复制译文按钮。翻译中显示「翻译中…」并禁用重复动作；图钉以浅蓝紫底 `pin` / 蓝底白色 `pin.fill` 表示状态，普通态可进入鼠标所在显示器的全屏 Space 并在失焦后 `orderOut`，置顶态加入所有 Space 且失焦不收起；轻灰 `doc.on.doc` 只复制译文，成功后短暂切换为浅蓝紫 `checkmark`。三个按钮均使用原生 momentary 按压态。
- 两个正文区域继续使用原生可选择、可滚动文本视图；未选中文字时 `Command+C` 仍复制当前栏全文。已有窗口只在新结果到达时更新标题、脚注和正文，不重新居中。
- 标准 macOS 可关闭、可缩放标题栏继续保留；实时字幕条仍沿独立路径固定置顶且未增加按钮。
- macOS 组合入口已移除独立 `InputTranslatePresenter` 的运行时构造，菜单「输入翻译…」直接调用结果 presenter 的 `show_input()`；划词和 OCR 继续调用同一实例的 `show()`。原 `interfaces/input_box.py` WIP 保留但不再参与 macOS 运行时，Windows Tk 输入窗口未改变。
- 「目标语言」标签和下拉栏移到原左上大标题位置，与右侧翻译、图钉、复制共用一行；来源脚注使用中间剩余空间。选项复用设置页的中文、英语、日语、韩语；切换只更新当前 `DesktopListener`，不自动翻译、不写 `.env`。翻译中栏位禁用并在结果返回后恢复；设置应用后 presenter 同步持久目标；实时 OCR 去重记忆在目标变化时清空。

## 运行时回归修复

- 用户首次重开 App 后报告划词热键无窗口；只读系统日志确认热键后的主线程回调反复抛出 `NameError: NSWindowTitleHidden is not defined`，因此故障发生在浮窗构造阶段，不是选区读取或翻译上游。
- 原因是最后一次代码清理把 `NSWindowTitleHidden` 与 `NSTitlebarSeparatorStyleLine` 导入在 `_AppKitBackend.__init__()` 的局部作用域，却在 `_build_window()` 中直接引用；此前快照生成早于该清理，纯布局测试也未执行标题栏构造，所以没有拦住回归。
- 标题栏处理已提取到 `_prepare_overlay_chrome()`，在使用位置读取 AppKit 运行时常量，并为较旧 PyObjC 提供与系统枚举一致的回退值；新增 Fake AppKit 合同固定标题隐藏、分隔线、透明状态和最小内容尺寸。
- 隔离 AppKit 冒烟使用 Fake 文本从后台线程调用正式 `show()`，实际走过 `callAfter` 和主线程建窗；结果为 `visible=true`，动态标题/原文/译文均写入，窗口从 normal 层级成功切换到 floating。
- 当时已运行的 App 进程在修复前启动，不会热加载新源码；本轮没有未经授权停止或重启它。用户随后已自行重开并完成双屏副屏全屏路径验收。
