# CLI 服务构造精简与优化复核

> 日期：2026-10-06（Asia/Shanghai）

## 改动与理由

当前 CLI 的通用、macOS 和 Windows 截图入口原本各构造 `ocr`、`ocr-translate` 和 `selection` 全部三类服务。工厂计数复现显示，即使只运行 `text` 或 `ocr`，也会创建两套 OCR 组合和两个翻译客户端；执行器实际只使用对应子命令的一类服务。

`app._common_services()` 现在根据首个子命令只构造需要的服务，macOS/Windows 复用这处组合，再用 `dataclasses.replace()` 补充原有平台回调。删除三处重复构造和 macOS 中仅用于暂存 CLI 服务的变量，保留桌面共享 `DesktopRuntime`、语言参数、图片读取、截图回调、CLI 参数/输出/退出码。没有新增依赖、缓存、公共契约或产品能力。

文档入口的当前状态压缩为能力与权威路由，减少版本、历史时延和既往验收步骤的重复叙述；这些事实继续保存在原计划、日志与稳定设计中。用户 README、架构、OCR/实时设计、计划状态与日志均同步；配置名、默认值、`.env.example`、版本和端口没有改变，不需要同步修改。

## 验证

- 修改实现前，文本、本地图片 OCR 与 OCR 后翻译的三平台工厂计数用例 9 项复现额外构造；实现后输出、执行次数和语言参数均正确。
- 后续加入 macOS/Windows 截图分支，使用 Fake 捕图、OCR 与翻译，确认平台回调保持可用；没有读取屏幕或剪贴板，没有加载 Windows Qt 原生环境。
- App、CLI、composition、桌面运行时及架构定向测试 56 项通过；最终完整离线 547 项通过（包含文档 6 项），`git diff --check` 通过。首次提醒仅重复函数返回值的断言已移除，路由行为断言和原生宽度/绘制验收继续保留。
- 精简前/后构造次数见下表。它证明避免了不必要初始化，不作为真实启动耗时或模型识别时延的基准。

| 命令 | 原 OCR / 翻译构造 | 当前 OCR / 翻译构造 |
| --- | --- | --- |
| `text` | 2 / 2 | 0 / 1 |
| `ocr` | 2 / 2 | 1 / 0 |
| `ocr-translate` | 2 / 2 | 1 / 1 |
