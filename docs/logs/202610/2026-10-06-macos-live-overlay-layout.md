# macOS 实时字幕条布局与复制优化

> 日期：2026-10-06（Asia/Shanghai）
>
> 状态：实现、离线与原生隔离验证完成，Git 交付收尾中

## 改动与取舍

Requester 要求“继续优化”，本轮从[核心路径后续优化计划](../../plan/in-progress/2026-10-06-core-optimization-follow-on.md)选择 macOS 实时字幕条长文布局，不扩展历史、剪贴板监听或模型能力。改动前窗口总高 88 点、内容区高 56 点，固定文本栏不足以承载长译文和错误信息。

字幕条改为复用普通工作区的只读、可选中、可换行滚动文本组件。按实际文本排版、标题栏和滚动区边框计算高度，总高 112～240 AppKit 点；原文显示区最多 40 点，优先让译文获得空间，长文均保留全文并可滚动到末尾。新结果或宽度变化后重算布局，保持置顶、不抢焦点，原文为空时隐藏原文区。布局按屏幕可见区域尝试下方、上方；空间不足时降低高度或改放右侧、左侧，仍不覆盖捕获区。圈选几乎占满屏幕而没有可用外侧空间时，窗口可能落在屏外，需缩小圈选。

复用组件时发现共享复制辅助函数按 Python 字符索引切片，而 AppKit 选区按 UTF-16 code unit 计数。最小修正按 UTF-16 截取选区，避免复制 emoji 或其后的文字发生错位；未选中时复制当前栏全文的行为不变。

OCR/翻译端口、四层路由、双模型配置、实时轮询和请求次数均未改变，没有新增依赖或框架。新增测试检查高度、区域外放置和复制输出，不添加源码字符串断言，也不批量重写无关 App 测试；有界历史继续由原待进行计划独立承接。

- 首次完整离线检查：556 项通过，1 项文档相对链接失败；原因是计划移入进行中后，指向另一份待进行计划的链接仍使用同目录路径，修正后文档 6 项通过，最终完整离线 557 项通过。
- 完整套件命令：`PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -p no:cacheprovider`；`git diff --check` 通过。
- 原生隔离验证使用项目 Python 3.13.14、实际 `LiveOverlayPresenter` / `NSPanel` / `NSTextView`、合成任务与禁用网络的临时脚本。覆盖 7 组内容：最小 280 宽短文、280 宽长中文与英文、720 宽显式多行、720 宽英文、翻译错误、空 OCR、emoji 选区。短文总高 112 点，长文达到上限 240 点；断言全文保留、只读可选中、不抢焦点和区域外放置。
- 长译文与原文分别滚动到尾部并绘制自身内容视图，已查看尾部标记；720 宽窗口缩至 280 后原生 resize 回调重算高度，加载短提示仍为 112 点，错误可读，空 OCR 清除两栏并隐藏原文。查看了最终绘制图，长文可换行，末尾可到达。
- 原生 `copy:` action 的两次输出写入内存，得到 `😀` 和 `BC`，未写入系统剪贴板；隐藏窗口未调用停止，原生关闭 action 恰好调用一次停止并收起窗口。

本轮不读取真实屏幕、剪贴板或用户选区，不运行真实 OCR/翻译、不下载模型、不重启安装 App。安装 App 的物理热键、鼠标圈选、跨应用/双屏全屏及真实上游未重新验收；纯矩形与原生隔离窗口验证不等于这些验证。
